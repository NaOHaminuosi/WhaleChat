# FAQ

按「问得最多」排序。这里写的是**结论 + 为什么**，不是使用说明（那个在 README）。

## 要花钱吗

App 本身免费、开源、无广告、无内购。但**DeepSeek 的 API 自己掏钱**——App 不代持任何账号，
也不做中转，你填的 Key 直接发往 `api.deepseek.com`。

语音识别同理：留在「系统」档不花钱；切到「讯飞听写」花讯飞的，默认每日 500 次免费，
个人用足够。

## 为什么不支持第三方兼容端点

只接 `api.deepseek.com`。

接一堆兼容端点意味着要为每个端点维护一份「模型名映射 / 参数差异 / 报错格式」，
而这些差异只会越来越多。这个项目的规模是一个人能看完的，保持单一后端才留得住。
真要接别的后端，fork 一份改 `DeepSeekClient` 里那一行 `MODEL_FLASH` 和 base URL 就行，MIT 允许。

## 为什么讯飞只支持「语音听写（流式版）」一档

讯飞控制台里另外两档大模型**实测接不通**，不是没做：

- 大模型（中英）V1.0（`iat.xf-yun.com/v1`）：用新账号的凭证握手，服务端直接回
  `10404 no category route found` 并断连。官方只对历史已购用户开放新开通。
- 大模型 V2：查不到可用的官方端点（照文档猜过一版，连主机名都不解析），代码已删。

与其放一个「能选但一定失败」的档位，不如不给。

## 为什么扫码是明文 HTTP，还能读走全部凭证

因为页面要**预填手表上当前的值**——看得见自己存进去的是什么，才知道到底存没存上。

所以那个 URL 既是写入入口也是读入口。压低风险靠四条：64 位随机 token、最长只活 10 分钟、
改凭证时收到一次合法提交立刻关停、只在扫码页存活。**别在公共 Wi-Fi 下用它。**

页面允许活到 10 分钟，是因为它同时要管角色人设：在手机上填六个大框是慢活，
两分钟填一半就断了等于白填。改角色的提交**不会**关停服务，方便接着改下一个。

## 会不会加表盘复杂功能（Complication）/ 卡片（Tile）/ 手机伴侣 App

1.0 没有，短期也不打算加。

- Complication 只有一块小地方显示，放不下对话；
- Tile 适合「看一眼」的静态信息，和「问一句等回答」不是一个交互；
- 手机伴侣 App 意味着要维护第二套 UI、第二套存储、还要处理两端同步——
  而扫码页已经把「在手机上填凭证」这件事解决掉了，代价小得多。

有更强的使用场景再来提 issue。

## 聊天记录存在哪，能备份吗

`filesDir/conversations.json`，应用沙箱内，其他 App 读不到，系统也备份不走
（`allowBackup=false`）。没有导出功能，卸载即清空。

要备份就 `adb pull /data/data/com.naoh.whalechat/files/conversations.json`——
但这条命令需要 root 或 debuggable 的包，普通 release 装上去是拉不出来的。
真想留着，复制文本更实际。

## 需要一直连着手机吗

不需要。这是 standalone 的手表应用，手表自己联网就能聊，手机上不用装任何配套软件。
唯一需要手机出场的时候是改凭证——那也只是打开扫一扫、填几个字、保存，
不涉及安装任何 App。

## 手表上打字太痛苦了

就是为了这个才有扫码页：设置 → 手机扫码改凭证 → 手机扫表上的码 → 在手机上填。
DeepSeek 的 Key 是 35 位 `sk-…`，讯飞那两串是 32 位十六进制，
在圆屏输入法上敲这些不是「有点麻烦」，是基本不可能。

## debug 包怎么这么卡

不是 bug，也不是代码问题：`debuggable=true` 时 ART 关掉了大部分编译优化，
Wear OS 那点算力立刻就露出来。**判断性能请装 release 包。**
（这也是为什么 CONTRIBUTING 里把这条写成硬规矩。）

## 我把 Key 填进去了，后来怀疑泄露了

去对应控制台吊销，重发一个。App 这边帮不上——它不持有你的账号，
也没有「远程吊销」这种东西。

顺带两条：

- 带预置凭证的包（`-PpresetXfyApiSecret=…` 出的那种）**不要外发**，凭证在 APK 里是明文；
- 报 issue 时别贴 `sk-…`、讯飞三串和扫码页 URL（那个 token 是完整凭证的读钥匙）。
